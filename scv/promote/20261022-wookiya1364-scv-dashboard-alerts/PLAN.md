# SCV 칸 — 끝·오류·허락 기다림 알림과 휴대폰 알림

## Summary

Claude가 2분 넘게 걸린 일을 끝냈을 때, 오류로 멈췄을 때, 허락 창을 띄웠을 때 알린다. 원격 연결 중이면 휴대폰까지 보낸다. 허락 창이 떠 있는 동안 칸에는 '실행 중' 대신 '허락 기다림'이 보인다. 지금은 일이 끝나도, 오류로 멈춰도 칸이 '쉬는 중'으로만 바뀐다(확인함). 허락 창이 떠 있는 동안에도 그 도구는 '실행 중'으로 보인다(형식 문서와 코드로 확인함).

## Goals / Non-Goals

- **Goals**
  - 끝 알림: 메인 차례가 답으로 끝났고 2분 이상 걸렸으면 알린다. 예: "끝났어요 · 3분 12초 · 다음: …"
  - 멈춤 알림: 오류로 끝나면 걸린 시간과 상관없이 "오류로 멈춤"을 알리고, 칸에 빨간 '멈춤 — 오류' 줄을 보인다. 답을 거절하고 끝난 경우도 같은 방식이다('거절로 멈춤'). 사용자가 직접 멈춘 경우는 알리지 않는다. 다음 차례가 시작되면 멈춤 줄은 사라진다.
  - 허락 기다림: 허락 창이 뜨면 칸에 '허락 기다림 — <도구>: <대상>'을 빨갛게 보이고(막힌 작업 카드), 알림을 보낸다. 그 도구가 끝나거나 거절되면 사라진다.
  - 휴대폰: 모든 SCV 알림(끝 · 멈춤 · 허락 · 답 기다림 · 시험 실패)을 Claude 자체 알림 도구로도 보낸다. 컴퓨터 알림(시스템 알림)과 토스트는 지금대로 둔다.
  - 차례 구분: 하위 에이전트의 차례 시작·끝을 메인 차례로 착각하지 않는다. 지금은 에이전트가 끝나기만 해도 칸이 '쉬는 중'으로 바뀔 수 있다(형식 문서로 확인함).
- **Non-Goals**
  - 외부 알림 서비스
  - 소리, 알림 끄기 설정

## Approach Overview

- 차례 끝의 이유(답 · 사용자 멈춤 · 거절 · 오류)와 걸린 시간으로, 알릴지와 무엇이라 알릴지를 정한다. 에이전트 표시가 없는 메인 차례만 본다.
- 허락 창이 뜨는 순간(허락 요청 신호)을 기록하고 알린다. 그 도구 호출이 끝나거나 거절되면 지운다.
- 알림은 한 곳에서 보낸다. 순서는 시스템 알림 → Claude 자체 알림 도구(200자 이하 한 줄) → 토스트다. 알림 도구가 없거나 실패해도 나머지 길로는 보낸다.
- 칸에는 멈춤 줄(빨강)을 보이고, 허락 기다림은 막힌 작업 카드와 진행 중 카드에 보인다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  isMainLoop,        // (이벤트) → 메인 차례인가
  classifyTurnEnd,   // (끝난 이유, 걸린 시간, 기준 2분) → 알림 없음 | 끝 | 멈춤
  buildAlertText,    // (알림 종류, 내용) → 200자 이하 한 줄
)
permissionWaitOf     // (허락 요청 도구, 입력, 시각) → 허락 기다림
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | 차례·허락 관찰 | 차례가 왜 끝났는지, 허락 창이 떴는지 지켜본다 | 훅 이벤트 → 사건 | 부수효과 (입구) |
| 2 | isMainLoop | 에이전트의 차례를 메인 차례와 구분한다 | 이벤트 → 메인인가 | 순수 |
| 3 | classifyTurnEnd | 끝난 이유와 걸린 시간으로 알릴지, 무엇이라 알릴지 정한다 | 이유, 걸린 시간, 기준 → 알림 없음 / 끝 / 멈춤 | 순수 |
| 4 | permissionWaitOf | 허락 창이 뜬 도구를 사람이 읽을 한 줄로 만든다 | 도구 이름·입력, 시각 → 허락 기다림 | 순수 |
| 5 | buildAlertText | 알림 문구를 200자 이하 한 줄로 만든다 | 종류, 내용 → 문구 | 순수 |
| 6 | findBlocks | 허락 기다림과 멈춤도 막힌 작업 카드에 넣는다 (재사용 · 넓힘) | 단계, 시험, 기다림 → Block[] | 순수 |
| 7 | 알리기 · 그리기 | 시스템 알림 · Claude 알림 도구 · 토스트로 보내고 칸을 다시 그린다 | 문구 → 알림 · 화면 | 부수효과 (출구) |

- 부수효과 위치: 차례·허락 훅과 시계(입구), 알림 세 길과 그리기(출구)
- 재사용: describeTool · findBlocks · formatDuration · 지금의 알림 묶음(alert)

## Guardrails

- 외부 알림 서비스는 쓰지 않는다.
- 허락 판단 자체는 바꾸지 않고 보기만 한다.
- 사용자가 직접 멈춘 차례는 알리지 않는다.
- 알림 길 하나가 실패해도 다른 길로는 보내고, 예외 때문에 칸이 멈추지 않게 한다(지난번 토스트 문제처럼).
- 지금 있는 시험은 계속 통과해야 하고, 버전은 올리지 않으며, 모드는 프로젝트 파일을 바꾸지 않는다.

## Exit criteria

- All TESTS.md scenarios pass
- 맥 앱 로컬 세션에서 시험 알림 한 번이 맥에 오는 것을 사용자가 확인한다. 원격 연결 중이면 휴대폰에도 오는지 확인한다. 안 오는 길은 결과를 적어 두고, 지금 방식(시스템 알림)을 유지한다.

## Risks / Open Questions

- 허락한 뒤 도구가 실제로 돌기 시작한 순간을 알려 주는 신호는 형식 문서에서 찾지 못했다. 그래서 긴 명령은 허락한 뒤에도 끝날 때까지 '허락 기다림'으로 남을 수 있다. 맥 앱에서 확인한 뒤 문구를 정한다.
- Claude 자체 알림 도구는 원격 연결 중일 때만 휴대폰으로 가고, 사용자가 화면 앞에 있으면 알아서 건너뛴다(도구 설명). 데스크톱 앱 세션에 이 도구가 있는지는 모른다.
- 이 세션처럼 허락을 묻지 않는 방식에서는 허락 기다림이 거의 생기지 않는다(확인함).
