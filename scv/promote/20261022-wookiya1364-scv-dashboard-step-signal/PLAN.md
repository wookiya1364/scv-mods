# SCV 칸 — 진행률이 실제 작업 중에 움직이기

## Summary

Claude가 계획의 단계를 시작하거나 끝낼 때마다 모드에 '단계 신호'를 보내게 한다. 그래서 SCV 칸의 진행률(n/N), 단계 흐름, 예상 완료 시간이 작업하는 동안 실제로 움직인다. 지금은 계획서에 누군가 완료 표시를 적어야만 움직인다. SCV는 표시를 적지 않고, 지난 계획의 ✓는 Claude가 손으로 적은 것이다(확인함). 아무도 적지 않으면 작업 내내 0/N, '예상 완료 시간: 아직 추정 불가'에 머문다.

## Goals / Non-Goals

- **Goals**
  - 모드가 Claude에게 '단계 신호' 도구를 준다. 받는 값은 계획 이름, 단계 번호(진행 경로 번호), 상태(진행 · 끝 · 막힘), 한 줄 메모(막힘이면 이유)다.
  - 진행 중인 계획(promote 폴더)이 있을 때만, Claude의 지시에 "단계를 시작하거나 끝낼 때 이 도구를 불러라"는 짧은 글을 붙인다.
  - 신호는 모드 저장소에 프로젝트 폴더와 계획별로 남긴다. 세션을 새로 열어도 이어진다.
  - 단계 상태는 계획서 표시와 신호를 합쳐 정한다. 어느 한쪽이라도 끝이면 끝이다. 막힘은 지금 단계에만 붙는다.
  - 예상 완료 시간은 신호 시각으로 단계당 걸린 시간을 재서 계산한다. 늘 '추정'으로 표시한다.
  - 표시나 신호가 하나라도 있으면 단계 흐름의 '(추정)' 꼬리표를 뗀다.
- **Non-Goals**
  - 모드가 계획서 파일에 ✓를 적는 것
  - SCV 플러그인 고치기
  - 신호 없이 파일 변화만 보고 단계를 맞히기(추측)

## Approach Overview

- 세션이 시작되면 모드 도구(단계 신호)를 등록한다. 허락 창 없이 통과시키는 것은 모드 자기 도구뿐이다.
- 받은 신호를 검사한다. 계획이 실제로 있는지, 단계 번호가 범위 안인지, 막힘·진행이 지금 단계(첫 미완료 단계)를 가리키는지 본다. 틀리면 이유를 돌려주고 기록하지 않는다.
- 맞는 신호는 기록에 더한다. 같은 단계라면 새 신호가 이전 것을 덮는다. 기록은 모드 저장소에 프로젝트 폴더별로 저장한다.
- 진행 중 계획이 있을 때만 Claude 지시 묶음(시스템 프롬프트)에 두세 줄을 덧붙인다. 내용은 계획 이름, 단계 수, 도구 부르는 법이다.
- 화면은 지금처럼 단계 흐름·진행률·예상 시간을 그린다. 다만 단계 표시는 '계획서 표시 + 신호'를 합친 값에서 읽는다.

## 순수함수 · 파이프라인 (Pure functions & pipeline)

```
flow(
  checkSignal,          // (신호, 계획 목록) → 맞음 | 틀림(이유)
  applySignal,          // (기록, 신호) → 기록
  mergeMarks,           // (계획, 기록) → 표시가 합쳐진 계획
  deriveStages,         // (계획) → Stage[]             (재사용)
  stepDurationsFromSignals, // (기록, 계획 이름) → 단계마다 걸린 시간
  estimateFromDurations,    // (걸린 시간들, 남은 단계) → 추정
)
buildStepPrompt         // (계획 목록) → 지시 글 | 없음
```

| # | 단계 | 하는 일 | 받는 값 → 돌려주는 값 | 순수/부수효과 |
|---|---|---|---|---|
| 1 | 신호 받기 | Claude가 부른 '단계 신호' 도구의 입력을 받는다 | 도구 입력 → 신호 | 부수효과 (입구) |
| 2 | checkSignal | 있는 계획·있는 단계를 가리키는지, 막힘·진행이 지금 단계에만 오는지 확인한다 | 신호, 계획 목록 → 맞음 / 틀림 이유 | 순수 |
| 3 | applySignal | 맞는 신호를 기록에 더한다. 같은 단계면 새 신호가 이긴다 | 기록, 신호 → 새 기록 | 순수 |
| 4 | mergeMarks | 계획서 표시와 기록을 합쳐 단계마다 상태를 정한다 | 계획, 기록 → 표시가 합쳐진 계획 | 순수 |
| 5 | stepDurationsFromSignals | 단계마다 걸린 시간을 잰다 — 시작 신호부터, 없으면 앞 단계 끝부터(한꺼번에 보고한 끝은 빼고) | 기록, 계획 이름 → 걸린 시간들 | 순수 |
| 6 | buildStepPrompt | 진행 중 계획이 있을 때만 Claude에게 붙일 짧은 지시를 만든다 | 계획 목록 → 지시 글 / 없음 | 순수 |
| 7 | 저장 · 그리기 | 기록을 모드 저장소에 두고, 지시를 붙이고, 칸을 다시 그린다 | 기록 · 지시 → 저장소 · 프롬프트 · 화면 | 부수효과 (출구) |

- 부수효과 위치: 도구 입력과 시계(입구), 모드 저장소·Claude 지시·그리기(출구)
- 재사용: deriveStages · countStages · estimateEta · formatDuration · 단계 흐름 그리기

## Guardrails

- 모드는 프로젝트 파일(계획서 포함)을 쓰지 않는다. 신호는 모드 저장소에만 둔다.
- 신호 도구는 허락 창을 띄우지 않는다. 모드가 허용하는 것은 자기 도구뿐이고, 다른 도구의 허락 판단은 건드리지 않는다.
- 지시 글은 진행 중 계획이 있을 때만 붙인다. 없으면 한 글자도 붙이지 않는다.
- 막힘은 지금 단계에만 붙는다. 시작하지 않은 뒤 단계로 온 막힘·진행 신호는 거절하고 이유를 돌려준다.
- 예상 완료 시간은 늘 '추정'으로, 근거(단계 몇 개 평균)와 함께 보인다.
- 지금 있는 시험 30개는 계속 통과해야 하고, 버전은 올리지 않는다.

## Exit criteria

- All TESTS.md scenarios pass
- 맥 앱 로컬 세션에서 남은 계획(알림 · 작업 보기 · 입력창·한도)을 구현하는 동안, SCV 칸의 n/N이 단계마다 오르고 예상 완료 시간이 실제 시간으로 바뀌는 것을 사용자와 함께 확인한다(화면 사진 1장).
